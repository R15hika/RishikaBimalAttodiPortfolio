Exam Revision Timeline ♡

Feature ·

A desktop revision planner: students enter their subjects, topics and exam times, and the app keeps them sorted in a binary search tree, warns about exam clashes and tells you what to revise next. I came up with the idea and built the whole app myself in C++ with the raw Win32 API, growing it from my C console version into a full GUI.

Project Overview ♡

  • A Win32 desktop app for planning exam revision: three screens (start, add subject, timeline) built directly on the Windows API.
  • Records are stored in a binary search tree ordered by start time (date × 1440 + minutes), so the timeline is always sorted.
  • Started as a C console program using a sorted array, qsort and a lower-bound binary search, then rebuilt as a GUI with a tree.
  • A 5-person group project. While I built the app, my teammates led the BST research, a study on using AI chatbots with academic integrity, and the report, presentation and project video.

My Contribution ♡

  • Came up with the idea, then designed and coded the whole app on my own: data model, BST, UI, validation and painting.
  • The BST: recursive insert, remove (with in-order successor), in-order traversal for the table, and a lower-bound search for Find Next.
  • Exam clash detection on overlapping time ranges, with a Yes / No / Cancel flow that holds the pending entry until the clash is resolved.
  • The Win32 UI: ListView with edit/delete icons, DateTimePicker limited to today onwards, input validation and a custom-painted gradient theme.

Experience Gained ♡

  • Choosing a data structure for the job: why a BST keeps data sorted on insert, and how its search beats a linear scan.
  • Writing recursive tree code safely, including the tricky two-child delete and freeing memory.
  • Building a GUI from raw Win32 messages: window procedures, common controls and WM_CTLCOLOR / GDI painting.
  • Thinking about user mistakes up front: clashes, duplicates and invalid times.
